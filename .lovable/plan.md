## Проблема

При сценарии **Клиент → «Добавить услугу» → Калькулятор → «Записаться на сервис» → Календарь** клик по слоту календаря визуально «ничего не делает», а вся страница «пропадает». Такое же поведение при «Калькулятор → Календарь» напрямую.

## Найденные причины (по аудиту кода)

### 1. `AppointmentDialog` пересбрасывает форму при каждом обновлении React Query
`src/components/AppointmentDialog.tsx`, useEffect в строках 159–221 имеет в зависимостях **`cars` и `allModels`** (query‑результаты). Каждый раз, когда любая мутация в приложении инвалидирует `["cars"]` или `["car-models"]`, эффект прогоняется заново и **обнуляет `selected`, `clientId`, `carId`, `comment`, `mileage`, `duration`, `status`**. Именно это выглядит как «всё исчезло» — открытый диалог сбрасывается в исходное состояние (или закрывается визуально при быстром перерисе).

### 2. `Calendar.openNew()` сразу вызывает `navigate({ search: {}, replace: true })`
`src/routes/calendar.tsx`, строки 194–197. `setDialog(...)` и `navigate(...)` вызываются в одном обработчике клика. При zod‑валидации search-params это триггерит перевалидацию/перерендер маршрута, что в комбинации с (1) может закрыть только что открытый диалог. Навигацию нужно откладывать до фактического открытия диалога (или переносить в `useEffect`).

### 3. Калькулятор передаёт `brand`/`carId` как `undefined`
`src/routes/calculator.tsx`, строки 1554–1561: `{ brand: brandId || undefined, carId: carId || undefined }`. Search‑схема календаря `fallback(z.string(), "").default("")` ожидает строки, а `undefined` в TanStack Router превращается в отсутствие ключа — это работает, но `model` не передаётся вовсе, из‑за чего prefill теряет модель, и авто‑поиск машины клиента в диалоге промахивается.

### 4. Prefill из клиента (`carId` в URL) прописан только «когда явно `carFromClient`»
При переходе из карточки клиента `carId` есть, но `brandId` в калькуляторе может ещё не подгрузиться (гонка запросов `brands`), и `carId` попадает в navigate как `""`, из‑за чего в календаре AppointmentDialog не автоподставляет машину.

## План правки

1. **`AppointmentDialog.tsx`** — переписать useEffect‑инициализатор:
   - убрать `cars`, `allModels` из зависимостей;
   - оставить только `[open, appointmentId, existing, defaultStart, defaultCarId, defaultServices, defaultBrandId, defaultModelId]`;
   - авто‑подбор машины по `defaultBrandId`/`defaultModelId` вынести в отдельный маленький эффект, который срабатывает **один раз**, когда `carId===""` и `cars`/`allModels` уже загружены (условный setState, чтобы не сбрасывать пользовательские правки).

2. **`calendar.tsx` → `openNew()`** — сначала открыть диалог, а очистку URL от prefill вынести в `useEffect` на `dialog.open === true && hasPrefill`, чтобы navigate не конкурировал с открытием диалога в том же тике.

3. **`calculator.tsx` → кнопка «Записаться на сервис»** — всегда передавать в `search` строки (пустые вместо `undefined`), добавить `model` (id найденной модели в БД, если есть) и не терять `carId` из URL:
   ```ts
   search: {
     services: parts.join(","),
     brand: brandId ?? "",
     model: dbModelId ?? "",
     carId: carId ?? "",
   }
   ```

4. **Диагностика в runtime** — прогнать сценарий в Playwright после правок: Клиент → Добавить услугу → выбрать услуги → «Записаться» → клик по слоту календаря; убедиться, что диалог открывается, машина и услуги подставлены, форма не сбрасывается.

5. **Мелкий защитный тюнинг**: в `Calendar` перед вызовом `openNew` проверить, что `slot.start` — валидная `Date`; логировать ошибки открытия диалога через `toast.error` в глобальном ErrorBoundary (если ещё нет).

## Файлы к изменению

- `src/components/AppointmentDialog.tsx` — реструктуризация init‑эффекта.
- `src/routes/calendar.tsx` — порядок `openNew` / navigate, effect для очистки search.
- `src/routes/calculator.tsx` — корректный `search` объект в navigate к `/calendar`.

## Проверка

- Playwright‑сценарий с логином, переходом Клиенты → Калькулятор → Календарь, клик по слоту, скриншот открытого диалога с prefill.
- Ручной прогон: изменить услугу в другом окне (инвалидация `["services"]`), убедиться, что открытый AppointmentDialog не сбрасывается.
