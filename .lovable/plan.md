## Диагностика

Аудит нашёл главную причину, почему «Прочие услуги» не появились в калькуляторе:

- **`src/routes/calculator.tsx:94-104`** — категории захардкожены в константе `CATEGORIES` (Жидкости, Двигатель, Тормоза, Подвеска, Электрика, Кузов, Диагностика, Дополнительно). Шаг 2 калькулятора (`:878`) итерируется только по этому списку — всё, что в БД не совпало по имени, игнорируется.
- **`src/routes/settings.tsx:786`** — категория при создании услуги вводится свободным текстом, без валидации и без связки с иконкой.
- **`src/components/BrandLogo.tsx:12`** — логотипы марок тянутся с внешнего CDN (jsDelivr), нельзя загрузить свой.
- Картинки категорий — статические `import` из `src/assets/*`, менять из UI нельзя.

## Что делаем

### 1. Новая таблица `service_categories` в БД
Поля: `id`, `name` (unique), `slug`, `image_url` (nullable), `sort_order`, `created_at`. GRANT `SELECT` для `anon`+`authenticated` (публично читаемо, как каталог), `INSERT/UPDATE/DELETE` — для `authenticated`. Сидинг: 8 текущих категорий + «Прочие услуги», с текущими картинками (после загрузки в Storage — см. п.2 — подставить URL).

### 2. Storage-бакет `catalog-images` (public)
Хранит: обложки категорий и логотипы марок, загруженные вручную. Всё через `supabase.storage.from('catalog-images').upload(...)`.

### 3. Поле `logo_url` в таблице `brands`
Опциональное. `BrandLogo` сначала показывает `logo_url` из БД, если пусто — фолбек на jsDelivr, если и там нет — инициалы.

### 4. Настройки → новая вкладка «Каталог»
В `src/routes/settings.tsx` добавляем вкладку с двумя секциями:
- **Категории услуг** — список с картинкой, полями «название», «порядок», кнопкой «Загрузить картинку» (в Storage), «Удалить». Кнопка «+ Добавить категорию».
- **Логотипы марок** — таблица марок с полем «Загрузить свой логотип» (перезаписывает CDN).

В существующей вкладке услуг: поле «Категория» становится `Select` с автозагрузкой из `service_categories` + опция «+ Новая категория» → мини-диалог, который создаёт запись в `service_categories`, а затем подставляет её в `services.category`.

### 5. Калькулятор — динамические категории
`src/routes/calculator.tsx`:
- Убрать константу `CATEGORIES` и локальные `import imgFluids`.
- Загружать `service_categories` через TanStack Query (кэш общий с настройками, инвалидация после добавления).
- Рендер шага 2 идёт по данным из БД, сортировка по `sort_order`.
- Fallback-картинка (одна нейтральная, положим в `src/assets/category-fallback.jpg`) — показывается, если `image_url` пустой.
- Если у услуги в БД `category` не совпадает ни с одной записью `service_categories` — автоматически группируем в «Прочие услуги» (создаём такую категорию в сидинге).

### 6. Инвалидация кэша
После любых изменений в настройках (`service_categories`, `brands.logo_url`, `services`) — `queryClient.invalidateQueries` соответствующих ключей, чтобы калькулятор мгновенно подтянул изменения без перезагрузки.

## Технические детали

- Миграция: `CREATE TABLE public.service_categories` + GRANT + RLS + policy (`SELECT` для anon, `ALL` для authenticated). `ALTER TABLE public.brands ADD COLUMN logo_url text`.
- Storage: создать бакет `catalog-images` через `supabase--storage_create_bucket` (public=true). RLS на `storage.objects`: `SELECT` для всех, `INSERT/UPDATE/DELETE` для `authenticated`.
- Сидинг категорий: одной миграцией вставить 9 строк (`Жидкости`, `Двигатель`, `Тормоза`, `Подвеска`, `Электрика`, `Кузов`, `Диагностика`, `Дополнительно`, `Прочие услуги`) с `sort_order` 10, 20, …, 90 и пустыми `image_url` (или, если хочется, я одноразово залью текущие 8 картинок из `src/assets` в Storage при первом запуске сборки — предпочту без этого шага, зальёте в UI).
- Ключи запросов: `["service_categories"]`, `["services"]`, `["brands"]`.
- Fallback-картинка калькулятора: возьмём одну из существующих или сгенерируем нейтральную (нейтральная шестерёнка).
