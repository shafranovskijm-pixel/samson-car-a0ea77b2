
## Что строим

CRM для автосервиса без авторизации. Есть каталог услуг и марок с ценами (можно редактировать), справочник машин клиентов, календарь записей + список по дням, назначение ответственного мастера. Всё сохраняется в базе Lovable Cloud.

## Данные (Lovable Cloud / Postgres)

- `brands` — марки авто (полный справочник, ~60 популярных: Toyota, Lada, Kia, Hyundai, BMW, Mercedes, Audi, VW, Skoda, Nissan, Mazda, Honda, Ford, Chevrolet, Renault, Peugeot, Citroen, Opel, Volvo, Mitsubishi, Subaru, Suzuki, Lexus, Infiniti, Land Rover, Jaguar, Porsche, Mini, Fiat, Jeep, Chery, Haval, Geely, Great Wall, Changan, Exeed, Omoda, Tank, JAC, GAC, BYD, Zeekr, Li Auto, Voyah, UAZ, GAZ, Moskvich, Datsun, SsangYong, Daewoo, Cadillac, Dodge, Chrysler, Genesis, Acura, Tesla и т.д.).
- `services` — услуги с базовыми ценами. Категории и позиции из типового прайса автосервиса (аналог Hyperauto): диагностика (компьютерная, ходовой, двигателя), ТО (ТО-1/ТО-2), замена масла ДВС/КПП/АКПП, тормозная система (колодки/диски/жидкость), подвеска (амортизаторы, сайлентблоки, рычаги), рулевое (рейка, наконечники), сцепление, ГРМ (ремень/цепь), электрика, кондиционер (заправка/диагностика), развал-схождение, шиномонтаж, кузовной ремонт базовый, полировка, вскрытие/эвакуация. Итого ~60–80 позиций.
- `service_prices` — переопределение цены услуги под конкретную марку (необязательно; если нет — берётся базовая).
- `clients` — ФИО, телефон, email.
- `cars` — client_id, brand_id, модель, год, госномер, VIN, цвет, объём двигателя, мощность, тип КПП, привод, текущий пробег.
- `mechanics` — ФИО, специализация, телефон.
- `appointments` — car_id, service_ids (несколько), mechanic_id, дата/время начала, длительность, статус (запланировано / в работе / выполнено / отменено), пробег на момент визита, комментарий, итоговая цена.

RLS отключаем (без авторизации, внутренний инструмент), но добавляем предупреждение в UI.

## Экраны

1. **Календарь** (`/`) — месяц/неделя/день, цветовая метка по мастеру, клик = карточка записи, drag-and-drop переноса; кнопка «Новая запись».
2. **Записи по дням** (`/schedule`) — список, сгруппированный по датам, фильтр по мастеру/статусу.
3. **Новая/редактирование записи** — выбор клиента (или создать), выбор машины клиента (или добавить), мультивыбор услуг с автоподсчётом итога по прайсу марки, ответственный мастер, дата/время, статус, комментарий.
4. **Клиенты** (`/clients`) — список, карточка с машинами и историей визитов.
5. **Машины** (`/cars`) — список всех авто с фильтром по марке.
6. **Услуги и цены** (`/services`) — таблица услуг с inline-редактированием базовой цены; вкладка «Цены по маркам» для переопределений; добавление/удаление услуг.
7. **Марки** (`/brands`) — управление справочником марок (добавить/переименовать/удалить).
8. **Мастера** (`/mechanics`) — CRUD.

Навигация — левый сайдбар (shadcn sidebar).

## Технические детали

- Стек: TanStack Start + Lovable Cloud (Supabase под капотом).
- Календарь: `react-big-calendar` (месяц/неделя/день, drag-and-drop).
- Формы: react-hook-form + zod, shadcn/ui компоненты.
- Данные: server functions через `createServerFn` + TanStack Query (`ensureQueryData` в loader, `useSuspenseQuery` в компоненте).
- Сидинг марок и услуг — миграцией при первом запуске.
- Все цены — целое число рублей.

## Этапы реализации

1. Включить Lovable Cloud, миграции таблиц, засеять марки и стартовый прайс услуг.

3. CRUD-экраны: услуги, марки, мастера, клиенты, машины.
4. Форма записи с расчётом стоимости.
5. Календарь + список по дням.
6. Полировка UX: подтверждения удаления, тосты, пустые состояния.
