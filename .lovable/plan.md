## Комиссия: итоговый диагноз

**Подтверждённая причина текущего белого экрана:** опубликованный ZIP содержит `SamsonCRM.exe`, но внутри архива нет web-сборки `dist-electron-web/client/index.html` и папки `assets`. Electron сейчас пытается грузить именно этот файл (`electron/main.cjs:25-26`), но `package:win` исключает всё, что начинается с `/dist` (`package.json:13`), поэтому `dist-electron-web` тоже выкинут из `app.asar`.

Дополнительный риск после исправления архива: при `file://` обычная browser-history маршрутизация может видеть путь к файлу как URL приложения. Для desktop-сборки нужно включить hash-history или явно загрузить приложение через hash-маршрут.

## Рабочий план

### 1. Починить упаковку Electron
- Исправить `package:win`, чтобы он больше не исключал `dist-electron-web`.
  - Сейчас `--ignore='^/dist'` совпадает и с `/dist-electron-web`.
  - Нужно заменить на точное исключение обычного web-dist: `^/dist($|/)`, либо переименовать electron outDir в имя, которое не начинается с `dist`.
- Оставить `scripts/fix-electron-paths.cjs`, но расширить проверку: после сборки она должна падать с ошибкой, если:
  - нет `dist-electron-web/client/index.html`;
  - в HTML остались `"/./assets/` или `"/assets/`;
  - любой `script/link href/src` указывает на несуществующий файл.
- Добавить отдельную проверку готового `app.asar`: внутри должны быть:
  - `electron/main.cjs`;
  - `dist-electron-web/client/index.html`;
  - `dist-electron-web/client/assets/*.js`;
  - `dist-electron-web/client/assets/*.css`.

### 2. Починить маршрутизацию под `file://`
- В `src/router.tsx` включить `createHashHistory()` только когда приложение запущено из файла:

```ts
window.location.protocol === "file:"
```

- В `electron/main.cjs` грузить `index.html` с начальным hash-маршрутом, например `/calculator` или `/login`.
- Для сайта в браузере оставить обычные URL без hash, чтобы опубликованный сайт не менялся.

### 3. Добавить понятную диагностику вместо белого экрана
- В `electron/main.cjs` перед `loadFile` проверить существование `index.html`.
- Если файла нет — показать встроенную HTML-страницу с точной ошибкой, а не белое окно.
- Повесить обработчики:
  - `did-fail-load`;
  - `render-process-gone`;
  - `console-message`;
  - `loadFile(...).catch(...)`.
- На время проверки открыть DevTools или писать лог рядом с приложением, чтобы увидеть ошибку сразу.

### 4. Сделать настоящий офлайн-режим, а не только кеш
Сейчас в проекте есть локальный логин и часть локального кеша, но основные данные CRM идут напрямую в облако. Для надёжной офлайн-работы нужно сделать local-first слой:

- Добавить локальную базу в Electron/браузере через IndexedDB.
- Хранить локально основные таблицы:
  - клиенты;
  - машины;
  - мастера;
  - записи;
  - услуги записи;
  - оплаты;
  - авансы;
  - справочник услуг;
  - марки/модели/модификации;
  - пользовательские услуги и цены.
- При первом запуске без интернета приложение должно открыться с:
  - локальным логином `admin555 / admin555`;
  - пустой рабочей базой;
  - встроенным начальным справочником марок/услуг из bundled JSON.
- Все изменения сначала сохранять локально, затем добавлять в постоянную очередь синхронизации.
- Когда интернет появляется — очередь отправляет изменения в облако и обновляет локальную базу.
- Денежные операции сделать особенно строго: оплаты, авансы и записи хранить как операции с датой, чтобы прибыль и ЗП не прыгали между месяцами.

### 5. Условие “без VPN”
- Все JS/CSS/картинки должны быть внутри exe/архива — тогда первый запуск не зависит от VPN.
- Для отправки данных в облако проверить доступность backend-адреса без VPN.
- Если backend в регионе клиента не открывается без VPN, сделать синхронизацию через ваш домен `api.samson-car.ru` как стабильный прокси/шлюз, чтобы приложение обращалось только к вашему домену.
- Пока соединения нет — данные не теряются, а остаются в локальной очереди.

### 6. Проверка перед словами “готово”
Я не буду считать задачу завершённой только после сборки архива. Минимальный чеклист готовности:

1. Собрать Electron web-dist.

3. Упаковать Windows ZIP.
4. Распаковать ZIP и проверить `resources/app.asar`:
   - `dist-electron-web/client/index.html` есть;

5. Собрать Linux Electron-пакет из той же сборки и запустить его в sandbox через headless/Xvfb.
