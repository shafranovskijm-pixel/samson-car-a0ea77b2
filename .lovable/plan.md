## Что не так сейчас

1. **Сохранение падает из-за RLS.** У таблиц `car_catalog_models`, `car_catalog_modifications`, `car_custom_services` и `service_usage_stats` политики требуют роль `authenticated`, а в приложении реального входа в Supabase нет — поэтому при сохранении модификации/кастомной услуги/статистики Supabase возвращает 401. Остальные таблицы CRM уже открыты как «Public full access» — то есть проблема точечная.
2. **У `car_catalog_modifications` нет политики DELETE**, хотя в настройках уже есть кнопка «Удалить модификацию» — она молча падает.
3. **UX ошибок в калькуляторе плохой** — при сохранении модификации показывается `alert("нужно войти")`, что вводит в заблуждение (реальная причина — RLS).
4. **Логина/пароля в приложении нет вообще** — вы просите добавить простой вход `admin555 / admin555`.

## Что сделаю

### 1. Миграция БД — открыть запись для клиентской части
Заменю политики на единый режим «Public full access» (как у `appointments`, `expenses`, `clients` и т.п.), плюс добавлю недостающие GRANT'ы для `anon`:

- `car_catalog_models`: снести `Authenticated can insert/update`, добавить `Public full access` (ALL, public, using true / with check true).
- `car_catalog_modifications`: то же + теперь появится DELETE (кнопка удаления заработает).
- `car_custom_services`: заменить три `authenticated`-политики на одну `Public full access`.
- `service_usage_stats`: заменить `usage_stats_write_auth` на public ALL (иначе `bump()` статистики популярности услуг падает).
- `GRANT INSERT, UPDATE, DELETE ... TO anon` на все четыре таблицы (SELECT уже был).

### 2. UX ошибок в калькуляторе (`src/routes/calculator.tsx`)
- Заменить `alert("Не удалось сохранить модификацию (нужно войти).")` на `toast.error(humanizeSupabaseError(e))` — теперь будет видна реальная причина, если что-то пойдёт не так.
- Пройти по всем `try/catch` в калькуляторе и убедиться, что везде используется `humanizeSupabaseError` + `toast.error`.

### 3. Аудит остальных «карточек» на предмет молчаливых ошибок
Пройдусь по мутациям в:
- `src/routes/clients.tsx` (клиент, машина, комментарий, категория)
- `src/routes/schedule.tsx` + `src/components/AppointmentDialog.tsx` (запись, услуги, платежи)
- `src/routes/mechanics.tsx` (мастер, ставка, аванс, ставка на услугу)
- `src/routes/expenses.tsx` (расход, аванс)
- `src/routes/settings.tsx` (марки, модели, услуги, цены, модификации)

Задача — убедиться, что везде на `onError` показывается `toast.error(humanizeSupabaseError(err))`. Где остались «тихие» catch — заменю на toast. Схему трогать не буду; фикс запись — это миграция выше.

### 4. Логин/пароль `admin555 / admin555`

Приложение деплоится как **статический билд на Timeweb** (`build:static` → `dist/client`), server-функции не работают, поэтому серверный gate из knowledge не подходит. Делаю **клиентский guard** — фиксированные креды в коде, флаг сессии в `localStorage`:

- Новый файл `src/lib/auth-gate.ts`:
  - Константы `LOGIN = "admin555"`, `PASSWORD = "admin555"` (приложение приватное, серверной проверки для статики всё равно не будет).
  - Функции `isUnlocked()`, `unlock(login, password)`, `lock()`, хук `useAuthGate()` с подпиской на `storage`-события (мультитабы).
- Новый роут `src/routes/login.tsx`:
  - Форма «Логин / Пароль» в стилистике калькулятора (тёмная).
  - При успехе — `navigate({ to: "/" })`. При ошибке — inline-сообщение «Неверный логин или пароль». Регистр логина игнорируем (можно и латиницей, и не-латиницей).
- `src/routes/__root.tsx`:
  - При маунте проверяем `isUnlocked()`. Если нет и текущий путь не `/login` — `navigate({ to: "/login", replace: true })`.
  - В сайдбар (`src/components/AppSidebar.tsx`) добавить кнопку «Выйти» → `lock()` + переход на `/login`.
- Роут `/login` — публичный (никакого guard-редиректа), остальные — за guard'ом.

### Замечание по безопасности
Клиентский пароль в статическом билде **не защищает данные от того, кто откроет DevTools** — это удобный барьер против случайных посетителей URL, не полноценная авторизация. Всё серьёзное разграничение по-прежнему пришлось бы делать в Supabase (RLS с реальным входом). Если позже захотите настоящую авторизацию (личные кабинеты, роли, ревок) — переключим на Supabase Auth.
