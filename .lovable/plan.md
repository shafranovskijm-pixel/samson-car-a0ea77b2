## Что происходит с «12 тыс.»

Проверил базу за июль 2026. В таблице `appointment_payments` лежат 5 платежей на **12 150 ₽** — именно их «Доходы» показывают как оборот кассы. Но:

- у записи `ca0d8961…` `total_price = 3 600 ₽`, а платежей на неё привязано **два: 3 600 + 3 750 = 7 350 ₽**.
- Триггер `recompute_appointment_payment` при уменьшении суммы услуг только «зажимает» `paid_amount` до `total_price`, но **лишние строки в `appointment_payments` не удаляет**. Из-за этого «Доходы» (сумма всех платежей месяца) продолжают учитывать переплату, а «Чистая прибыль» завышена.

То есть услуги действительно удалили/уменьшили, но платежи-«хвосты» остались висеть в кассе.

## План

### 1. Починить учёт кассы (расходы/прибыль)

1. В `listPaymentsRange` (`src/lib/api.ts`) фильтровать платежи так, чтобы:
   - не учитывались платежи по `appointments.deleted_at IS NOT NULL`;
   - для каждой записи сумма учитываемых платежей не превышала актуальный `total_price` (обрезать «переплату» по FIFO: старые платежи целиком, последний — до остатка).
2. `revenue` в `src/routes/expenses.tsx` считать по этому очищенному списку → «Доходы» и «Чистая прибыль» перестанут учитывать удалённые/лишние услуги.
3. Добавить одноразовую служебную миграцию/чистку: удалить из `appointment_payments` строки, где `appointment_id` относится к удалённой записи, и обрезать переплаты (сумма платежей по записи ≤ `total_price`). Триггер `recompute_appointment_payment` после этого сам обновит `paid_amount`/`payment_status`.
4. В диалоге платежей: не давать сохранить сумму больше остатка `total_price − paid_amount` (защита от повторения бага).

### 2. Переработать «Сводную таблицу» — колонка на каждого мастера

Сейчас мастера идут вперемешку по строкам. Сделаю таблицу-«пивот» по мастерам.

Структура:

```text
Число | Марка / машина | Гос. № | Работа        │  Александр           │  Кирилл              │
                                                │  %  Сумма  ЗП  Аванс │  %  Сумма  ЗП  Аванс │
27.07 | Nissan Dualis  | н258…  | замена ступ…  │ 50% 2 000  1 000  —  │  —    —    —    —    │
27.07 | Toyota Sprinter| B499…  | шаровая опора │  —    —    —    —    │ 30% 2 350  705  —    │
…
ИТОГО                                            │      X    Y     Z    │      X    Y     Z    │
ВСЕГО (все мастера): Сумма … / ЗП … / Аванс …
```

Правила:
- Каждый мастер = группа из 4 подколонок: **%**, **Сумма**, **ЗП**, **Аванс**.
- Строка = дата + машина + работа; значения падают только в колонку своего мастера, у остальных пусто.
- Аванс мастера за день по-прежнему приклеивается один раз (к первой работе этого мастера в этот день); «висячие» авансы (день без работ) — отдельной строкой с пустой «Работой».
- Внизу — строка «ИТОГО» с суммами по каждому мастеру и общий итог.
- Фильтр «Все мастера / …» остаётся: при выборе одного мастера показываем только его 4 колонки и его строки.
- Экспорт в Excel и печать переделываю под тот же пивот (те же группы колонок, второй ряд заголовка с %/Сумма/ЗП/Аванс, объединённые ячейки заголовка мастера).
- На узком экране включаю горизонтальный скролл (`overflow-x-auto`) и «липкие» первые 4 колонки, чтобы шапка не разъезжалась.
