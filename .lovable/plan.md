## Что добавляем

### 1. Диалог «Новая машина» в разделе «Клиенты»

В форме `CarDialog` (`src/routes/clients.tsx`) сейчас Марка — обычный `Select` по существующим брендам, а Модель — простой input с datalist. Добавим создание на лету:

- **Марка**: заменить `Select` на `Combobox` с поиском. В выпадашке — существующие бренды + пункт «+ Добавить марку "<текст>"», который через `createBrand` создаёт бренд и сразу подставляет его id в форму (с `toast` об ошибке-дубликате).
- **Модель**: сохранить свободный ввод, но при сохранении машины, если введённого имени нет среди `car_catalog_models` для этого бренда — автоматически вызвать `dbEnsureModel(brand, modelName)` (уже существует), чтобы модель попала в БД каталога и стала видна калькулятору.
- **Модификация (год + двигатель + кузов)**: добавить свернутый блок «Сохранить в каталог модификаций». Если пользователь заполнил Год + хотя бы одно поле из {объём, л.с., тип КПП, привод, кузов}, при сохранении дополнительно вызываем `dbAddModification({brand, modelName, year, displacement_cc, horsepower, note: color?, ...})`, чтобы модификация появилась в калькуляторе.

Все три действия идут одной цепочкой в `onSubmit` формы. Ошибки прогоняем через `humanizeSupabaseError`.

### 2. «Добавить модификацию» в настройках калькулятора

В `src/routes/settings.tsx`, компонент `ModelsManager` (диалог «Модели · <Марка>»): рядом с каждой моделью добавить кнопку **«Модификации»** — открывает вложенный диалог со списком модификаций по годам и формой добавления, аналогичной той, что в `src/routes/calculator.tsx` (строки 656–790).

Вложенный компонент `ModificationsManager({ brand, modelName })`:
- Селектор года (все годы из `dbListYearsForBrand` + возможность ввести новый).
- Список модификаций текущего года через `dbListModifications`.
- Форма «Новая модификация»: Кузов, Двигатель (код), Объём (л → cc), Л.с., Топливо, Гибрид, Руль, Заметка. Сабмит → `dbAddModification`.
- Удаление модификации: добавим `dbDeleteModification(id)` в `src/lib/carsCatalogDb.ts` (простой `delete from car_catalog_modifications`), кнопка «Удалить» с `useConfirm`.

Общий блок формы модификации выносим в `src/components/ModificationForm.tsx`, чтобы калькулятор и настройки использовали одну форму (рефакторинг существующего JSX из `calculator.tsx`).

## Технические детали

- Все записи идут в существующие таблицы: `brands`, `car_catalog_models`, `car_catalog_modifications`. Миграции не нужны.
- Combobox для марки — на базе уже используемого `cmdk` (проверю наличие; иначе — `Popover + Command` из shadcn, они в проекте есть).
- `dbEnsureModel` уже upsert-ит модель без дублей; `dbAddModification` использует `onConflict: model_id,year,raw` — дубли безопасны.
- Инвалидация: после создания в диалоге клиента — `qc.invalidateQueries({ queryKey: ["brands"] })` и очистка кэшей `["car-catalog-*"]`, чтобы калькулятор увидел новую марку/модель без перезагрузки.
