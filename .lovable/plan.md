## 1. Автосоздание напоминания из записи

В `AppointmentDialog` добавить блок «Напоминание клиенту» (сворачиваемый):
- Чекбокс «Создать напоминание»
- Интервал после записи: день / неделя / месяц / полгода / год (Select)
- Название (авто: «ТО через N — <имя клиента>», редактируется)
- Примечание (опционально)

При сохранении записи, если чекбокс включён — вставляем строку в `client_reminders` с `remind_at = appointment.starts_at + интервал`, `client_id` из записи. В карточке клиента (`clients.tsx`) эти напоминания уже отображаются в блоке «Напоминания».

Для существующих записей — кнопка «+ Напоминание» в диалоге редактирования работает так же.

## 2. Канал доставки напоминаний (Telegram / Email)

Сейчас напоминания только хранятся в БД — не отправляются. Для доставки нужно:

**Рекомендация:**
- **Telegram** — бесплатно, мгновенно. Через встроенный коннектор Telegram Bot (уже доступен в проекте). Клиент один раз пишет боту `/start`, получает `chat_id`, админ сохраняет его в карточке клиента (поле `telegram_chat_id`).
- **Email** — через Resend (тоже коннектор), отправка с собственного домена. Проще для клиента (не нужно ничего подключать), но письма могут попадать в спам.

**Как это работает:**
1. Добавляю поле `telegram_chat_id` и/или используем существующий `email` клиента.
2. Cron-задача (pg_cron) раз в 5 минут вызывает публичный роут `/api/public/hooks/send-reminders`, который находит напоминания с `remind_at <= now()` и `sent_at IS NULL`, отправляет их через Telegram/Resend и проставляет `sent_at`.
3. В карточке клиента — переключатели «Канал: Telegram / Email / Оба».

**Что выбрать:** для СТО в России Telegram — оптимально (мгновенно, читаемо, дёшево). Email — как резерв.

Реализация канала доставки — отдельным шагом после подтверждения выбора (Telegram, Email или оба).

## 3. Drag & Drop в календаре

Календарь (`calendar.tsx`) сейчас — сетка мастер×час. Добавить перетаскивание записи:
- Библиотека `@dnd-kit/core` (лёгкая, SSR-совместимая).
- Каждая карточка записи — `useDraggable`, каждая ячейка `<мастер, час>` — `useDroppable`.
- При отпускании: пересчитать `starts_at` (новый час, дата = текущий день календаря, минуты сохраняются), `mechanic_id` = мастер целевой колонки, `ends_at` = сдвиг на ту же длительность. Вызвать `updateAppointment`, инвалидировать `["appointments"]`.
- Визуал: полупрозрачная тень при перетаскивании, подсветка целевой ячейки.
- Клик по карточке (без drag) продолжает открывать `AppointmentDialog` — используем `activationConstraint: { distance: 5 }`.
