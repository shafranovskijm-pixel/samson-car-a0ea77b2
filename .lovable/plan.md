
## Что сделаем

Упакуем CRM в десктопное приложение (Electron) с локальной базой и автосинхронизацией с Lovable Cloud при появлении интернета. Пользователь получит `.exe` для Windows, работает без VPN и без интернета, а при онлайне данные подтягиваются в облако и обратно.

## Архитектура

```text
[Electron .exe]
  └── Vite build (dist/) — тот же React UI
       ├── Локальное хранилище (IndexedDB через Dexie)
       │     клиенты, машины, записи, платежи, услуги, расходы, авансы...
       ├── Очередь изменений (outbox): create/update/delete + timestamp
       └── Sync worker:
             online?  →  push outbox в Supabase
                      →  pull изменений из Supabase (updated_at > last_sync)
                      →  merge (last-write-wins по updated_at)
             offline? →  копим в outbox, UI работает с локальной БД
```

## Что меняется в коде

1. **Слой данных**: сейчас `src/lib/api.ts` ходит напрямую в Supabase. Оборачиваем его в репозиторий, который сначала пишет/читает локально (Dexie), а Supabase — как «удалённый» источник для sync.
2. **Sync-модуль** `src/lib/sync.ts`:
   - `pushOutbox()` — отправляет накопленные операции;
   - `pullChanges()` — тянет новые/изменённые строки по `updated_at`;
   - слушатели `window.online/offline` + периодический `setInterval` (например, каждые 30 сек, когда онлайн).
3. **UI-индикатор** в шапке: «Онлайн / Оффлайн / Синхронизация… / Не синхронизировано: N».
4. **Схема БД**: во всех основных таблицах должен быть `updated_at` (у большинства уже есть) и мягкое удаление `deleted_at`, чтобы синхронизация корректно распространяла удаления. Добавлю миграцию, где не хватает.
5. **Electron-обёртка** (`electron/main.cjs`, `base: './'` в Vite, `@electron/packager`) — упаковка в Windows `.exe`. Соберу `.zip` со standalone-приложением (портативный запуск без установщика).

## Ограничения, которые важно понимать

- **Стратегия конфликтов — last-write-wins** по `updated_at`. Если один и тот же клиент правится оффлайн на двух машинах, победит более поздняя правка. Полноценный CRDT — это отдельный большой проект.
- **Логин `admin555 / admin555` — локальный** (не Supabase Auth). Синхронизация идёт под публичными политиками таблиц, как сейчас. Это ок для одного бизнеса, но данные технически доступны всем, кто знает ключ. Если нужно закрыть — заведём реальную учётку и переключим RLS.
- **Первый запуск** должен быть онлайн — чтобы приложение скачало начальный слепок данных. Дальше можно работать оффлайн сколько угодно.
- **Только Windows `.exe`** в этом плане. macOS/Linux — по запросу отдельно.
- Печать заказ-нарядов, калькулятор, каталог машин, кастомные услуги — всё продолжает работать оффлайн (каталог кэшируется локально при первом входе).

## Что получит пользователь

- Файл `SamsonCRM-win-x64.zip` (или установщик, если попросите) — распаковал, запустил `SamsonCRM.exe`, работает.
- Значок оффлайн/онлайн и счётчик несинхронизированных изменений в шапке.
- Кнопка «Синхронизировать сейчас».

## Технические детали (для справки)

- Dexie 4 + собственный слой репозиториев, чтобы `api.ts` не знал про транспорт.
- Supabase-клиент используется только внутри sync-модуля.
- Electron: `contextIsolation: true`, `nodeIntegration: false`, `base: './'` в `vite.config.ts` (создам отдельный конфиг, чтобы не ломать веб-сборку).
- Пакуем через `@electron/packager` (electron-builder в песочнице не работает).
- Готовый архив кладём в `/mnt/documents/SamsonCRM-win-x64.zip` для скачивания.
